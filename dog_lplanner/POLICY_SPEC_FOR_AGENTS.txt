# SAC Path-Planning Policy — Spec for LLM Agents

Минимальный текстовый спецификационный файл. Используй его при написании кода для данной политики (инференс, экспорт, интеграция с лидаром и т.д.).

--- Quick reference ---
• Actor input: [56] = base [47] + action_history [9]. Base: lidar(40) + w(1) + sin(1) + cos(1) + dist(1) + prev(3). No vx, vy.
• Actor output: [3] in [-1, 1] → scale by cmd_scale [0.8, 0.4, 0.35].
• Lidar: 40 sectors, raw [0.25, 3.0] m → normalize to [-1, 1] (-1=close, +1=far). Collision: min(raw) < 0.35.
• Config: configs/a1.yaml. history_length=3, critic_history_length=3.
--- end ---

---

## 1. Обучение

- **Алгоритм:** SAC (Soft Actor-Critic).
- **Среда:** MuJoCo, Unitree A1, сцена с препятствиями (кубы). Робот и цель спавнятся в свободных точках.
- **Два уровня управления:**
  1. **SAC (high-level):** по наблюдению выдаёт команды скорости `[vx, vy, w]` в `[-1, 1]`.
  2. **Walking policy (low-level):** предобученная MLP. Вход: `velocity_commands` (от SAC) + base_ang_vel, projected_gravity, joint_pos, joint_vel, last_action. Выход: 12 целевых углов суставов. PD-контроллер их отслеживает.
- **Частоты:** sim 500 Hz, control 50 Hz, SAC 10 Hz (каждые `control_decimation * sac_decimation` шагов). Лидар для SAC кэшируется на частоте SAC.
- **Эпизод:** до `max_steps`, завершается при `reached` (расстояние до цели < 0.2 м), `collision` (см. лидар) или таймауте.

Конфиг: `configs/a1.yaml`. Ключевые параметры — `cmd_scale`, `sac.history_length`, `sac.critic_history_length`, `reward_weights`, `lidar.noise_std`.

## 2. Observations (наблюдения)

### 2.1 Базовое наблюдение Actor (47 признаков)

Порядок строгий:

| Индексы | Размер | Описание |
|--------|--------|----------|
| 0–39   | 40     | Лидар по секторам (нормализовано, см. раздел 4) |
| 40     | 1      | Угловая скорость `w` (норм. по `max_angular_vel`, обычно = `cmd_scale[2]`) |
| 41     | 1      | `sin(angle_to_target)` в локальной системе робота |
| 42     | 1      | `cos(angle_to_target)` в локальной системе робота |
| 43     | 1      | Расстояние до цели (норм. по `max_distance`), затем `*2 - 1` → `[-1, 1]` |
| 44–46  | 3      | Предыдущая команда SAC `[vx, vy, w]` в `[-1, 1]` |

- **Важно:** Actor **не** получает `vx`, `vy` (линейные скорости). Только `w`, лидар, цель, `prev_action`.
- `angle_to_target`, `distance`: из `get_target_info(robot_pos, target_pos, robot_quat)`. Угол в локальной системе: x — вперёд, y — влево. `sin = dy_local/distance`, `cos = dx_local/distance`.

### 2.2 История действий (Actor)

- `sac.history_length = 3`.
- Вход сети: `base(47) + history(3 * 3) = 56` признаков.
- История: последние 3 команды `[vx, vy, w]`, в хронологическом порядке (сначала старые):  
  `[vx_{t-3}, vy_{t-3}, w_{t-3}, vx_{t-2}, vy_{t-2}, w_{t-2}, vx_{t-1}, vy_{t-1}, w_{t-1}]`.
- При неполной истории дополняем нулями **слева**.

### 2.3 Critic

- Базовое: Actor(47) + `vx`(1) + `vy`(1) = 49. Дополнительно: `critical_topk` ближайших лидарных лучей, история наблюдений (`critic_history_length`). В инференсе нужен только Actor.

### 2.4 Нормализации

- Лидар: см. раздел 4.
- `w`: `clip(w, -max_angular_vel, max_angular_vel) / max_angular_vel` → `[-1, 1]`.
- `distance`: `clip(d, 0, max_distance) / max_distance` затем `*2 - 1` → `[-1, 1]`. `max_distance` ≈ 10.75 м (диагональ комнаты).
- `sin`/`cos`: уже в `[-1, 1]`, при необходимости `clip(..., -1, 1)`.
- `prev_action`: храним и подаём в `[-1, 1]`.

## 3. Actions (действия)

- **Выход SAC:** `[vx_cmd, vy_cmd, w_cmd]` в `[-1, 1]`.
- **Масштабирование (обязательно):**  
  `vx = vx_cmd * cmd_scale[0]`, `vy = vy_cmd * cmd_scale[1]`, `w = w_cmd * cmd_scale[2]`.  
  В `a1.yaml`: `cmd_scale: [0.8, 0.4, 0.35]` (м/с, м/с, рад/с).
- Эти `[vx, vy, w]` подаются в walking policy как `velocity_commands`. Walking policy выдаёт 12 joint targets; мы не меняем её, только обеспечиваем корректный ввод.

## 4. Лидар в обучении и инференсе

### 4.1 Сырые данные

- 40 лучей (MuJoCo lidar-сенсоры) или эквивалент (например, 2D проекция облака точек).
- Единицы: метры. Диапазон: `[min_range, max_range]` = `[0.25, 3.0]` м. Ближе 0.25 м — корпус робота, отбрасываем.
- `inf`/`nan`/отрицательные: перед пайплайном заменяются (например, `fix_negative_lidar_values`: соседи или 3.0), затем `clip` в `[0, 3]`.

### 4.2 Секторы (process_lidar_to_sectors)

- 40 секторов, углы `[-π, π]` равномерно. Сектор `i`:  
  `[-π + i * (2π/40), -π + (i+1) * (2π/40))`, последний включает `π`.
- Для каждого сектора берётся **минимальное** расстояние среди лучей, попавших в сектор. Если лучей нет — `max_range` (3.0 м).
- На выходе: вектор длины 40 (метры).

### 4.3 Шум (опционально)

- В обучении (и при желании в симе): гауссов шум `N(0, lidar.noise_std)` к сырым расстояниям, затем `clip` в `[0, max_range]`. В `a1.yaml`: `noise_std: 0.02`.

### 4.4 Нормализация для политики

- По каждому сектору:  
  `x = clip(dist, 0, max_range) / max_range` → `[0, 1]`,  
  затем `x * 2 - 1` → `[-1, 1]`.  
  **-1 = близко, +1 = далеко/нет препятствия.**

### 4.5 Коллизия и награда

- **Коллизия:** `min(валидные лидарные значения) < 0.35` м → конец эпизода, крупный штраф (`reward_weights.collision`, например -500).
- Награда использует **сырой** лидар (в метрах), в т.ч. для obstacle penalty. В наблюдение политики всегда подаётся **нормализованный** лидар (секторы в `[-1, 1]`).

### 4.6 Совместимость с ROS2

- `lidar_2d_processor` строит 40 секторов так же (фильтр пола, 2D, секторы, минимумы). Формат совпадает с `process_lidar_to_sectors`. При переносе на реальный лидар нужно сохранить тот же пайплайн (секторы → метры → нормализация).

## 5. Типичные подводные камни

1. **Actor без vx/vy:** в observation только `w`, лидар, цель, `prev_action`. Не добавлять линейные скорости в Actor.
2. **История действий:** строго 3 последних `[vx, vy, w]`, порядок старый → новый, паддинг нулями слева. Размер входа Actor при `history_length=3`: 56.
3. **cmd_scale:** всегда применять к выходу SAC; в конфиге `[0.8, 0.4, 0.35]`, не путать со старыми 1.7/1.5.
4. **Лидар:** в сеть — нормализованные 40 значений `[-1, 1]`; коллизия/награда — сырые метры; секторы считаются по одной и той же схеме (40 секторов, минимум, 0.25–3.0 м).
5. **Цель:** `distance`, `sin`, `cos` в локальной системе робота; при `distance < 1e-6` использовать `sin=0`, `cos=1`.
6. **Частота:** политика вызывается на 10 Hz; лидар и целевая информация должны быть согласованы по времени (в т.ч. при интеграции с внешним лидаром).
